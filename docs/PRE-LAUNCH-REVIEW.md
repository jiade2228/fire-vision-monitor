## 二、阻塞问题（必须解决后才能上线）

### BLOCK-1 【严重】110 个变更全部未提交，无版本控制快照与回滚路径

- **证据**：`git status --short` → 69 个 `M` + 41 个 `??`；最近提交 `a2083fa` 停留在 **11-09 15:57**；`server/config.mjs`、`server/net-guard.mjs`、`server/restore-builtin-templates.mjs`、`docs/REVIEW-CHECKLIST.md` 等**核心新文件均为未跟踪状态**。
- **影响范围**：全部近期整改（含 2 个 P1 安全修复、V10 迁移配套、SSE 缓存、录像增量对账）。
- **风险**：
  - 无提交点 → 无 diff 快照 → **无法回滚**到发布前状态；
  - 11-09 的历史提交不含 V10 会话表、能力矩阵、config 模块 —— 一旦发布失败回退到 HEAD，会直接破坏当前生产库（V10 schema 用旧代码打开缺表）；
  - CI（`.github/workflows/ci.yml`）基于 push 触发，未提交 = **CI 从未验证过这批代码**。
- **修复建议**：
  1. 提交一个明确的发布 commit（建议 `git add -A && git commit -m "发布：安全加固与系统治理（P1/P2/P3 全量）"`）；
  2. 打 tag（如 `v1.1.0`），记录 commit hash；
  3. 用 `git show <tag>:...` 确认新文件已进入提交；
  4. **确认回滚目标**：明确"回滚到哪个 commit 仍能兼容 V10 库"—— 若没有，需准备一个最小迁移兼容补丁作为回滚预案。

### BLOCK-2 【严重】生产实例运行旧代码，待发布代码从未在真实数据目录上持续运行

- **证据**：生产实例 `/healthz` uptime **30091 秒（约 8.4 小时）**，启动于 11-11 15:00；今晚 21:00 后的全部整改（SSE sid、限流第四维、升级重试、内置模板防护等）**未部署**。watchdog 日志显示 11-11 14:58/14:59 两次 `no live instance, starting service`，15:00 后稳定。
- **影响范围**：所有今晚改动。当前生产实例不具备这些修复。
- **风险**：本地隔离环境验证通过 ≠ 真实负载/真实数据下稳定。特别注意：
  - SSE 广播新增逐 client 的 `isSessionRevoked` 查询（真实 6 点位 + 多客户端下未做压力验证）；
  - 全局限流阈值 500/10min 在真实登录频率下的误伤率未知；
  - `claimNotification` 失败重试语义变化在真实 webhook 故障场景下未验证。
- **修复建议**：按 BLOCK-1 提交后，部署到生产并**至少观察一个完整业务周期**（含一次定时任务轮次：`retentionRun` 90s、`mediaWatermark` 30s、`backup` 15s、`recordingReconcile` 20s、`recordingRetention` 120s），确认无 `config_invalid`、`fatal_shutdown`、`unhandledRejection` 日志。

### BLOCK-3 【高】上线前必做验证项尚未完成（见 §3 清单）

以下验证在本次审查中**无法完成**，但不是代码缺陷，而是缺少环境/数据/时间：

## 六、最终结论

**不可上线（当前状态）。**

理由不是代码质量不达标 —— 相反，235 条测试全绿、真实库兼容、核心链路实测通过、11 项整改全部落地且验证。
阻塞的是**发布可控性**：

1. **110 个变更未提交**，CI 从未验证这批代码，且无可用回滚点（回退到 HEAD 会因 V10 schema 不兼容而破坏生产库）；
2. **生产实例运行旧代码**，所有今晚的安全与稳定性修复尚未生效，且新代码未在真实数据目录上持续运行过；
3. **V1–V10 上线前验证项全部未完成**，其中 V7/V8/V9 需真机与部署信息，本次审查无法代替。

### 上线路径（按顺序）

1. 完成 BLOCK-1：提交 + 打 tag + 确认回滚方案 + 备份当前生产库（`VACUUM INTO`）；
2. 完成 V1（CI 全绿）与 V2（回滚预案）；
3. 部署并重启，完成 V3–V6（启动观察、业务冒烟、SSE 隔离、通知回归）；
4. 取得真机/部署信息后完成 V7–V9；若现场条件暂不具备，应**明确记录为已知风险并在上线后首个班次补足**，而非默认通过；
5. V10（24h 长稳）完成后，方可认定为"成熟产品可投入使用"。

在完成第 1–3 步后，可以给出**"可灰度上线、需持续观察"**的结论；在完成第 4–5 步后，才能给出**"可正式上线"**的结论。
