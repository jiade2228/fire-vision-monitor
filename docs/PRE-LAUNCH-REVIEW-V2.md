## 六、对上次报告的修正（实证推翻）

**上次判断**：「回滚到 HEAD 会因缺少 V10 schema 而破坏生产库」。

**实证结果**：我用 `git worktree` 检出 HEAD（`a2083fa`，`SCHEMA_VERSION=8`），用其 `openStore` 打开生产库的 `VACUUM INTO` 快照 —— **成功，版本 10、1 用户、6 点位数据完整**。原因是各迁移函数都有 `if (version >= N) return` 守卫，version=10 时全部跳过。

**准确结论**：
- 回滚到 HEAD **数据安全、可启动**；
- 但会**回退全部安全修复**（SSRF 规范化校验、会话级撤销、config 校验、画面异常映射等）；
- 且 HEAD 不认识 `auth_sessions` → 已登录会话被忽略（用户需重新登录）、撤销名单失效（安全回退）；
- 无 V9 索引 → 性能回退。

因此回滚是**可用但降级的应急手段**，不是"会破坏数据"。已在 §3 BLOCK-1 的风险描述中按此修正。
