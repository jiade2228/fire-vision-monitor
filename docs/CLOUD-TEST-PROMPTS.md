## 二、提示词 A：Web 应用功能验收（推荐，用便携包）

复制以下整段发给云端测试方：

```text
【任务】
对 Flame Vision 火情视频识别监控平台 v1.2.0 做功能验收测试，输出结构化缺陷报告。
你需要在 Windows 机器上解压并启动它，然后用浏览器完成下列用例。

【被测对象】
- 便携包（免安装，推荐）：https://github.com/jiade2228/fire-vision-monitor/releases/download/v1.2.0/fire-vision-1.2.0-win-x64-portable.zip
- 源码仓库（只读参考）：https://github.com/jiade2228/fire-vision-monitor

【环境要求】
- Windows 10 / 11 x64，允许运行本地进程与监听本地端口
- 不需要安装 Node.js（包内自带运行时）
- 不需要安装 FFmpeg（本次构建不含，见「已知限制」）
- 端口 4173，服务监听 0.0.0.0

【启动步骤】
1. 解压 zip 到任意可写目录（路径不要含空格过多的深层嵌套）
2. 双击 start.cmd；或在包目录执行：program\node.exe program\server\boot.mjs --port 4173
3. 浏览器打开 http://127.0.0.1:4173
4. 首次访问进入初始化向导，创建管理员账号（用户名 ≥ 3 字符，密码需满足页面提示的强度要求）
5. 健康检查：GET http://127.0.0.1:4173/healthz 应返回包含 "ok":true 的 JSON

【测试用例】

A. 认证与会话
 A1 首次初始化创建管理员 → 应成功并自动登录
 A2 再次调用初始化接口 POST /api/setup → 应被拒绝，且不得覆盖已有管理员
 A3 用错误密码登录 → 401，提示不泄露"用户名是否存在"
 A4 连续多次错误登录 → 应触发限流或锁定，记录响应码与等待时间
 A5 登出后访问 GET /api/alarms → 401，响应体应含 code 字段
 A6 修改密码后，旧会话是否失效（记录实际行为，不预设对错）

B. 权限与多站点隔离
 B1 新建第二个站点，创建站点管理员，验证其只能看到本站点的点位与告警
 B2 普通用户访问用户管理接口 GET /api/users → 403
 B3 跨站点读取他人点位详情（直接构造 ID 请求）→ 应 403 或 404

C. 点位管理
 C1 新建点位（协议选 none）→ 201，列表可见
 C2 名称留空 → 400；名称填 500 字符 → 拒绝或截断（记录实际长度）
 C3 协议填非法值（如 javascript:alert(1)）→ 400
 C4 停用 / 启用点位 → 刷新后状态持久化
 C5 点位存在未处置告警时删除 → 应 409 拒绝并提示数量
 C6 处置完告警后再删除 → 成功，且该点位的告警与录像索引被清理

D. 告警全流程
 D1 在点位页触发一条 fire 或 smoke 告警（走界面路径）
 D2 告警列表：分页、按等级 / 状态 / 时间筛选均可用
 D3 处置：确认 → 归档；尝试从"待处置"直接归档应被拒绝
 D4 GET /api/alarms/stats?days=7 → 返回含 series 与 windowDays 字段
 D5 边界参数不得 500：limit=-1、limit=999999、时间窗 from>to

E. 界面与可用性
 E1 刷新后登录态保持；同时开 3 个标签页操作无异常
 E2 深色 / 浅色主题切换，文字可读、无对比度过低
 E3 窄屏 375px 宽度下布局不重叠、无横向滚动条

F. 持久化
 F1 停止服务（关闭窗口或结束进程）后重启 → 管理员、点位、告警全部保留
 F2 包目录下 data\ 内应存在 app.db 与 credentials.key，logs\ 内应有日志

【已知限制 —— 出现下列现象属于预期，不得作为缺陷上报】
1. 本包不含 FFmpeg：RTSP/HLS 转码、持续录像、告警短视频、一键测流、录像回放不可用。
   相关入口报错、转圈或列表为空，属预期取舍（为控制体积，含 FFmpeg 的包会超过 500 MB）。
2. 未做代码签名：Windows SmartScreen 提示"未知发布者"属预期。
3. 单实例限制：同一 data 目录重复启动会被 instance.lock 拒绝，属预期保护。
4. 未随包提供测试视频样本，演示/示例素材可能为空。
5. 通知渠道需要真实 SMTP / Webhook 才能验证送达；无外部依赖时只验证配置保存与错误提示是否清晰。
6. 包内 README-QUICKSTART.txt 写有"program/ 含 FFmpeg"，与实际不符（文案问题，已知）。

【缺陷分级】
- P0 无法启动、无法登录、数据丢失或损坏
- P1 核心流程阻断（告警无法处置、越权访问、接口 500）
- P2 功能与预期不符但存在绕过方式
- P3 文案、样式、体验问题

【输出格式】
1. 缺陷清单，每条包含：编号 | 严重度 | 标题 | 复现步骤 | 期望结果 | 实际结果 | 证据（截图 / 响应体 / 日志片段）
2. 通过的用例清单（只列编号即可）
3. 未覆盖的用例及原因
4. 环境信息：Windows 版本、是否管理员、浏览器及版本

【日志位置】
包目录\logs\、包目录\data\server.out.log、包目录\data\server.err.log
```

## 三、提示词 B：安装包安装 / 卸载测试

适用于有管理员权限的 Windows 虚拟机或快照环境。

```text
【任务】
验证 Flame Vision v1.2.0 Windows 安装包的安装、运行、升级与卸载行为。
请在一台可回滚的 Windows 虚拟机或快照中进行，并记录所有系统变更。

【被测对象】
https://github.com/jiade2228/fire-vision-monitor/releases/download/v1.2.0/fire-vision-1.2.0-win-x64-setup.exe

【环境要求】
- Windows 10 / 11 x64，具备管理员权限
- 建议先做系统快照，测试后可回滚

【用例】
1. 安装
   1.1 双击 exe，记录是否触发 UAC 提示
   1.2 默认安装路径是否为 C:\Program Files\FireVision
   1.3 是否创建开始菜单项与桌面快捷方式
   1.4 安装过程中是否出现乱码（中文界面应正常显示）
2. 首次运行
   2.1 从开始菜单启动，浏览器是否能打开 http://127.0.0.1:4173
   2.2 完成初始化创建管理员
   2.3 检查数据目录：应位于 %LOCALAPPDATA%\FireVision，且包含 app.db 与 credentials.key
       —— 确认没有试图写入 Program Files（该目录默认只读）
3. 开机自启（安装时勾选）
   3.1 检查启动文件夹是否生成快捷方式：%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
   3.2 注销后重新登录，服务是否自动启动
4. 升级（可选）
   4.1 再次运行同一安装包覆盖安装
   4.2 确认原有账号、点位、告警数据未丢失
5. 卸载
   5.1 通过"设置 → 应用"卸载
   5.2 卸载完成后确认：程序目录已删除、开始菜单项已删除、启动项已删除
   5.3 确认数据目录 %LOCALAPPDATA%\FireVision 仍然存在（卸载不删数据属预期设计）
   5.4 记录卸载后仍残留的文件与注册表项路径

【已知限制 —— 不得作为缺陷】
- 未签名：SmartScreen 提示"未知发布者"属预期
- 不含 FFmpeg：视频相关功能不可用属预期
- 卸载保留用户数据：这是有意设计，避免误删录像与数据库

【输出格式】
按用例编号输出「通过 / 失败 / 未执行」，失败项附截图与系统日志；
另附：安装耗时、安装后体积、残留项清单。
```

## 四、提示词 C：代码与安全审查（可选）

```text
【任务】
审查仓库 https://github.com/jiade2228/fire-vision-monitor （Node.js + React，SQLite）的
安全性与健壮性，输出可复现的问题清单。

【重点关注】
1. 认证与会话：会话令牌生成、撤销、过期；登出是否真正失效；并发登录处理
2. 授权：多站点隔离是否在数据层生效（而非仅前端隐藏）；能力矩阵是否有遗漏
3. 注入：SQL 是否全部参数化；是否有字符串拼接进入查询
4. SSRF：出网请求（ONVIF、通知 Webhook）是否校验目标地址，能否绕过到内网/云元数据地址
5. CSRF：写操作是否强制自定义请求头校验
6. 文件操作：路径穿越、上传大小限制、临时文件清理
7. 错误处理：是否泄露堆栈或内部路径；异常是否导致进程退出
8. 数据一致性：事务边界、并发写入、迁移脚本的版本守卫

【不要上报的已知取舍】
- 不含 FFmpeg 导致视频功能不可用（打包取舍）
- 未做代码签名（移交项）
- 无多副本/集群支持（单实例设计，SQLite 单写）

【输出格式】
按严重度分级（严重 / 高 / 中 / 低），每条给出：位置（文件:行）| 问题 | 影响 | 复现或验证方式 | 修复建议。
仅报告能在代码中定位的问题，不要基于猜测下结论。
```

## 五、发给云端前的三点提醒

1. **优先用便携包**。安装包需要管理员权限，多数云沙箱会拒绝；便携包解压即可运行。
2. **务必把「已知限制」一并给对方**。否则大概率会收到"RTSP 不可用""录像打不开"这类误报，来回沟通成本很高。
3. **端口 4173 需要放行**。服务监听 `0.0.0.0`，但云主机的安全组 / 防火墙默认可能未开放该端口。
